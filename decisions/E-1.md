# E-1 — Der Dienst auf dem Server entsteht in Python, mit Flask

**Entschieden am 11.09.2026 zusammen mit E-5.
Betrifft APP-2, APP-10, TB-7 und Abschnitt 5 der App-Spec.**

## Entscheidung

Python. Als Web-Rahmen **Flask**.

## Warum

E-1 stand offen, weil ein Node-Frontend das Argument geliefert hätte, sich eine
Sprache zu teilen. Mit **E-5** — einem Frontend ohne Build-Schritt — fällt dieses
Argument weg, und es bleibt nichts, was für Node spräche.

Damit greift, was `offen.md` von Anfang an empfohlen hat: Die Nachbarprojekte
sind Python, und die Wiederverwendung des Provider-Musters hängt daran (TB-7).
Ebenso der fertige Weg zur Azure-Sprachausgabe.

**Flask statt FastAPI**, weil die Nachbarprojekte Flask fahren und TeachBuddy
daneben auf derselben Maschine läuft. Ein zweites
Web-Framework im Haus wäre eine Entscheidung gewesen, die niemand gefordert hat
(TB-9).

## Was daraus folgt

Das gebaute Frontend wird als statische Dateien vom selben Flask-Dienst
ausgeliefert, der auch die API trägt. Ein Dienst, ein Prozess (APP-10).
